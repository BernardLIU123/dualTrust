## 3. 算法核心

### 3.1 原理

Dual Thrust 日内突破策略：用开盘后前 15 分钟的 1 分钟 bar 高低点构成当日区间，价格突破区间放大后的轨道时入场。区间固定、一天计算一次，保留 Dual Thrust"锚定 + 放大"的核心逻辑。

### 3.2 轨道计算

以交易日 D 的 21:00–21:15（含首尾）共 15 根 1 分钟 bar：

```
RangeHigh = max(区间内 high)      RangeLow = min(区间内 low)
Range     = RangeHigh - RangeLow

上轨 Upper = RangeHigh + K1 × Range
下轨 Lower = RangeLow  - K2 × Range
```

- 21:00–21:15 为**观察期**（`COLLECTING`），区间未定前无轨道、不交易
- 21:15 起轨道激活（`ARMED`），开始监控突破
- 区间一天只计算一次，全天固定不变

### 3.3 交易规则

1. **开仓**：1 分钟 bar 收盘价向上突破 `Upper` → 开多 `fixed_size` 手；向下跌破 `Lower` → 开空。**每交易日每方向最多一次**；当日两方向都被触发时反手（先开的一方平仓转另一方）
2. **止损**：`stop_distance = max(ATR(30) × stop_atr_mult, 0.5 × Range)`，即开仓价 ∓ stop_distance 为初始止损线，触发即市价平仓，当日不再开新仓。ATR 基于 1 分钟 bar 计算（vn.py ArrayManager）
3. **强制平仓**：14:55 市价平仓，绝不隔夜——规避夜盘跳空与隔夜保证金风险
4. **开盘价定义**：以夜盘 21:00 开盘作为当日起点（与交易所日线口径一致），区间在 21:00–21:15 收集

### 3.4 参数表

| 参数 | 含义 | 默认 | 优化范围 |
|------|------|------|---------|
| `window_minutes` | 开盘区间分钟数 | 15 | 10 / 15 / 30 |
| `k1` | 上轨系数 | 0.5 | 0.2–0.9，步长 0.1 |
| `k2` | 下轨系数 | 0.5 | 0.2–0.9，步长 0.1 |
| `atr_length` | ATR 周期（1 分钟 bar） | 30 | 20–60 |
| `stop_atr_mult` | 止损 ATR 倍数 | 2.0 | 1.5–2.5 |
| `fixed_size` | 固定手数 | 1 | 1–5 |
| `force_close_time` | 强平时间 | 14:55 | 14:50–14:59 |

### 3.5 RU 合约特性映射（实盘参数默认值）

- 合约单位 10 吨/手；最小变动价位 5 元/吨（= 50 元/手）
- 交易时段：日盘 9:00–10:15 / 10:30–11:30 / 13:30–15:00；夜盘 21:00–23:00
- 手续费默认 3 元/手双边（上期所标准，以交易所最新公告为准，配置项可改）
- 保证金率默认 10%（交易所约 7% + 期货公司上浮，配置项可改）
- 主力合约换月：回测用主力连续序列（前复权消除换月跳空）；实盘在交割月前切换至新主力
- 涨跌停保护：临近涨跌停价位不追单、不开仓

## 4. 系统架构

### 4.1 组件与职责

```
┌─────────────────────────── 应用层（GUI/脚本） ───────────────────────────┐
│  CtaBacktester（回测+参数优化）   CtaStrategyPro（实盘）  RiskManager（风控）│
├─────────────────────────── 引擎层 ────────────────────────────────────┤
│  CtaEngine：策略调度、bar 推送、发单路由         OmsEngine：委托/成交/持仓 │
│  DataManager：历史数据管理（SQLite 存储）        AlgoTrading：可选 │
├─────────────────────────── 策略层 ────────────────────────────────────┤
│  DualThrustStrategy(CtaTemplate)：算法核心（回测实盘同一份代码）        │
├─────────────────────────── 接口层 ────────────────────────────────────┤
│  CTP Gateway（实盘） / CTP SimNow（仿真先行）                          │
└──────────────────────────────────────────────────────────────────────┘
```

### 4.2 策略类日内状态机

RU 交易日跨夜（21:00 → 次日 15:00），策略实现严格的日内状态机：

| 状态 | 触发条件 | 行为 |
|------|---------|------|
| `COLLECTING` | 21:00 开盘 | 收集前 15 根 1 分钟 bar，只观察不交易 |
| `ARMED` | 21:15（区间确定） | 计算上下轨，激活突破监控；ATR 开始累积 |
| `LONG` / `SHORT` | 突破触发 | 持有多/空，跟踪止损线 |
| `STOPPED` | 止损或反手 | 当日不再同向开仓 |
| `CLOSED` | 14:55 强平 | 平仓，等待下一交易日 21:00 重置 |

- **交易日切换检测**：用 `on_bar` 的 datetime 判断（进入新交易时段 21:00 时重置全部日内状态、重算轨道）。vn.py 无内建"交易日切换"事件，需自实现 + 交易日历校验
- **实盘 tick→1 分钟 bar**：CTP tick 经 `BarGenerator` 合成，与回测 bar 口径完全一致
- **回放一致性**：回测引擎按序回放 bar，21:00–21:14 的 bar 走 `COLLECTING`，与实盘路径相同——同一状态机、同一代码，保证回测实盘无逻辑漂移

### 4.3 数据管道

```
分钟数据文件(CSV) ──→ tools/import_data.py ──→ vnpy SQLite 数据库 ──→ 回测引擎
```

- 标准文件格式：`datetime, open, high, low, close, volume, open_interest`（UTC+8，`YYYY-MM-DD HH:MM:SS`）
- 支持单合约（如 ru2601）与主力连续序列
- 导入脚本校验：时间戳单调、价格合法性（high ≥ low ≥ 0）、缺失 bar 检测、重复行拒绝

## 5. 风控、监控与容灾

### 5.1 三层风控体系

**第一层：策略内（代码级）**
- 止损：`max(ATR(30) × 2, 0.5 × Range)`，市价平仓，当日不再开仓
- 每方向每日最多一次
- 14:55 强平，绝不隔夜
- 涨跌停保护：临近涨跌停不追单、不开仓
- 单策略最大持仓 = fixed_size

**第二层：RiskManager 模块（引擎级，vn.py 自带）**
- 流控：每秒/每分钟最大委托笔数
- 单笔最大手数、当日总委托手数上限
- 活动委托数上限（防重复发单）
- 下单前保证金充足性检查

**第三层：账户级（盘前人工复核）**
- 每日最大亏损熔断（默认日亏超权益 2% → 当日停策略）
- 账户级最大回撤线（默认 20% → 全面停策略并复盘）

### 5.2 监控与告警

事件引擎 → 钉钉/邮件推送：

| 告警项 | 级别 | 动作 |
|--------|------|------|
| 开仓/平仓成交回报 | 信息 | 推送成交详情 |
| 止损触发 | 警告 | 立即推送 |
| 14:50 仍持仓（强平预警） | 警告 | 推送，人工介入确认 |
| 行情中断（连续 5 分钟无 bar） | 严重 | 停止开仓 + 推送 |
| 网关断线/重连 | 严重/信息 | 推送 |
| 委托被拒/废单 | 严重 | 推送 + 停止开仓 |

盘中状态面板：持仓、上下轨位置、当日信号次数、已实现盈亏。

### 5.3 容灾设计

- **断线重连**：CTP Gateway 自动重连；重连成功后校验本地持仓与柜台持仓一致性，不一致 → 告警停机
- **行情保护**：连续 5 分钟无新 bar → 禁止开仓，持仓进入纯风控模式（止损/强平仍生效）
- **进程守护**：Windows 任务计划/服务方式启动，崩溃自动拉起，启动时恢复策略状态
- **审计日志**：完整委托/成交/状态机转换日志，每日归档
- **交易日历**：节假日/临时休市日历，非交易日跳过；集合竞价时段（20:55–21:00）不发单

## 6. 回测方法与绩效评估

### 6.1 回测设置

| 项目 | 设定 |
|------|------|
| 引擎 | vn.py CtaBacktester（与实盘同一策略代码） |
| 数据 | 自供 1 分钟数据，主力连续序列（换月跳空前复权） |
| 回测区间 | ≥ 3 年（覆盖趋势市 + 震荡市完整周期） |
| 手续费 | 3 元/手双边（可配置） |
| 滑点 | 默认 1 tick（50 元/手）；另跑 0 / 2 tick 敏感性 |
| 保证金率 | 10% |
| 起始资金 | 10 万（1 手 RU 保证金约 1.7 万，缓冲充足） |

### 6.2 绩效指标

- 收益类：总收益率、年化收益率、月度收益分布
- 风险类：最大回撤、最大单日亏损、年化波动率
- 风险调整：夏普比率（rf = 2.5%）、卡玛比率、索提诺比率
- 交易类：交易次数、胜率、盈亏比、平均持仓时长、日均信号数
- 成本敏感性：`(手续费 + 滑点) / 毛利润`，> 30% 视为对执行成本过于敏感

### 6.3 样本内 / 样本外与验收门槛

```
完整区间（3 年+）
├── 样本内（前 70%）：网格搜索参数寻优
└── 样本外（后 30%）：参数固定，一次性验证，结果作废后不再调参
```

验收门槛（Phase 0 退出条件，任一不达标 → 返回优化，不进入仿真）：

| 指标 | 门槛 |
|------|------|
| 夏普比率（样本外） | ≥ 1.0 |
| 最大回撤 | ≤ 20% |
| 样本外夏普 / 样本内夏普 | ≥ 60% |
| 成本占比 | ≤ 30% |
| 分年度正收益年份占比 | ≥ 60% |
| 参数微扰稳定性（±0.1） | 夏普变化 ≤ 25% |

另需：分年度绩效表（不依赖单一特定行情）；基准对比（同期买入持有 + 经典日线版 Dual Thrust 对照，证明分钟级改造的增量价值）。

### 6.4 回测工具化

`tools/run_backtest.py`：网格寻优 → 最优参数样本外验证 → 绩效报告（CSV + 权益曲线图 + 分年度表），参数与数据版本号固化在报告头，结果可复现。

## 7. 测试与验收标准

### 7.1 单元测试（tests/，pytest）

| 测试对象 | 验证内容 |
|---------|---------|
| 轨道计算 | 已知 bar 序列下 Upper/Lower 精确值；边界：区间内最高=最低、异常数据 |

| 交易日历 | 节假日跳过、临时休市处理 |

### 7.2 仿真盘验收（Phase 1 退出条件）

- SimNow 连续运行 ≥ 1 个月，状态机零异常、零废单
- 信号一致性回放：实盘日志与回测引擎同行情重放，信号一致率 = 100%
- 断线重连、行情中断保护、14:55 强平实测通过
- 告警推送全部触发验证

### 7.3 实盘试运行验收（Phase 2 退出条件）

- 实盘滑点 ≤ 回测假设（1 tick）
- 成交率 100%，监控告警零漏报
